# Estimating doctrine

Estimating is not guessing. It is analyzing documents, quantifying scope, applying cost data, and producing a probable cost of construction. An estimate is an opinion of cost, not a guarantee.

## Hierarchy

1. Order of Magnitude (±30–50%)
2. Schematic / conceptual (±15–30%)
3. Design development (±10–15%)
4. Construction documents (±5–10%)
5. Bid (±3–5%)

State which level you are working at. Do not present an OM number as a bid.

## Takeoff principles

- Count everything once
- Use the right unit
- Trace every quantity to a source
- Separate measured, calculated, counted, and scheduled
- Flag every assumption
- Never hide a plan-vs-schedule conflict

## Scale

- No valid scale = no real-world measurements
- Verify scale against a known dimension
- Conflicting scales: stop
- NTS: counts only

## Cost data

- Must have source, date, and location
- Adjust for location, market, and complexity only when those factors are stated
- Never invent pricing
- Mark allowances clearly
- Keep historical data separate from current bids

## The estimate is never done

Every estimate has a date, document version, and revision. Changes after publication need a documented revision.
